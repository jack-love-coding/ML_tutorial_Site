# 2026-10-16 手机端密集图与教案复查

## 范围和方法

以 `fe13e26aac192cda3acd932a516c78fd55a619fa` 为基线，从六个 pilot 单元的 120 节阅读清单派生 81 个不同页面地址。在 390px、reduced motion 下逐页访问，滚动触发图片懒加载后测量实际宽高和资源路径。共取得 80 个不同图片资源及 173 个含文字的原生 SVG 实例；没有页面脚本异常。这里的计数是覆盖清单，不等于每幅图的教学效果都已通过人工或学生验收。

对概率、向量、清洗／缩放图逐幅核对正文与数值，并实看手机截图。另抽看 AI 概览、Python 图表、房价项目的手机图组。单元 6 本轮没有发现新的密集图片资源；交互绘图、Canvas 与外部 Notebook 的完整可读性不能仅用 `img` 清单证明。

## 首项：概率基础

- 多栏长图缩到约 334px 后，图内说明很难阅读，且中文烘焙文字不会随语言切换。
- 原 softmax 长图的分数和概率条不对应；校准图混淆一组预测的正确率与单样本的真实类别概率；均值／方差图容易让人误以为低方差直接代表模型更准。
- 以六张窄幅 SVG 分别解释分布、事件指示量、样本频率、相同期望下的方差、校准、softmax 与目标概率。图中文字至少 20 个 SVG 单位，双语解释与精确数表保留为原生文字。
- 原始假设、图、表来自同一数据定义。NumPy 固定种子 7 的十二个输出保持原样：九个 1，频率 0.75；模型概率为 0.70。三类 logits `[1.5, 0.3, -0.8]` 经现有 softmax／cross entropy 工具计算，真实标签设为 C2，`q=0.0715392094795326`、`−ln(q)=2.6375095952607857`。
- 教案明确二元 NumPy 示例与六分桶实验不同；增加样本不保证每步误差都减小。校准采用明确标注的十条假设记录，不能冒充评估报告。交叉熵完整推导链接到逻辑回归之后的分类损失课。
- 概率首节两个重叠概览合为一张，原 why 图锚点映射到保留的概览。十二章、交互实验、原始图片文件和冻结代码输出不删除。

数学图采用确定性 SVG，由实际数值生成，生成器带 `--check`。不重新生成 Notebook、模型结果或无关 PNG／视频。普通测试中的 28 项条件跳过仍列为本批未验证；冻结产物校验与严格离线重生成是不同验收。

本地首项验收：`npm test` 1,185 通过、28 条件跳过；`npm run build`、`npm run build:pages`、`npm run curriculum:check`、8 项发布资源检查及生成器 `--check` 通过。131 个相关浏览器场景通过（单元 5 阅读 60、数学加载／锚点 9、条件概率 9、跨课衔接 44、新概率图 9），覆盖双语、1280px／390px、键盘重置、reduced motion、旧锚点与刷新、图片失败后原生数表可读、空存储和预置历史记录逐字节不变。六张新图均检查了实际手机截图。

## 第二项：清洗与缩放

优先修复实际计算错误：`CleaningPipelineLab` 原来把房间数固定填为 3，而展示的 pandas 代码使用中位数；现有有效值 `[2,3,4,9]` 的中位数为 3.5。现在由共享计算产生填充值，实验与数据质量场景复用，16 种开关组合逐项与 pandas 运行结果一致。原始教学表不变；插补、裁剪、去重与日期解析的影响分别说明，并添加键盘可操作的重置。

两个密集图分别改为清洗四动作图和训练缩放图。数值课不再重复清洗策略，回链数据质量课；缩放图与既有实验共用 `rooms` 的训练值、总体标准差和验证变换。教案说明 ddof=0、插补值不等于观察值、真实极端值不必删除，以及处理完仍有缺失。清洗片段、缩放示例与冻结房价项目是独立案例。旧清洗动画保留，并明确格子只是示意；实际四动作保持 6 列。

原生图注在图片失败时继续完整显示；新 SVG 的图中文字至少 20 个单位，不再叠加可能遮挡图形的编号。旧图文件和资源 ID 保留。

本地数据课验收：全量测试 1,188 通过、28 条件跳过，两种构建、目录与 8 项发布资源检查通过。78 个相关浏览器场景通过（单元 2 连续阅读 40、原数据课视觉／实验 20、新清洗与缩放 18），涵盖双语、桌面／390px、键盘开关和重置、回看链接、刷新、图片失败，以及空存储和历史记录逐字节不变。清洗所有 16 种开关组合与独立 pandas 结果一致；缩放统计与 NumPy 总体标准差一致。

补充抽查单元 6 的 18 个手机页面：使用可换行的原生流程面板，无横向溢出；实看树分裂、预处理边界和阈值面板。另在回归和房价三个页面、两种语言中用键盘展开既有图表文字版，数值可读且没有页面溢出；这不代表原图的小刻度问题已经解决。

## 第三项：向量桥接与 shape

原首节使用学习次数、错题数、测验分数 `[2,5,80]`，后面的 shape 与预测却切换为关卡输入 `[2,3]`；三张概览在首节并列，shape 一节又重复长图。本次统一使用函数课的 A=`[2,3]`、B=`[1,4]`，固定基础任务数／提示请求数的顺序，目标 `[9,7]` 单独保存。

两张 360 单位宽的确定性 SVG 分别讲坐标和样本／特征轴，合计 3,980 bytes；替换的三张正文 PNG 合计 3,701,186 bytes，旧文件保留。图内最小字号 20 个单位，原生双语图注解释差向量 `[-1,1]`、`(2,)` 与 `(1,2)` 的区别，以及方阵转置虽然 shape 不变却改变语义。权重、偏置与 `[10,5]` 的计算留给既有批量预测图，避免每幅图重复完整流程。

浏览器验收发现两项阅读问题并修复：图片锚点原来会退出四节选读，且“下一节”误指首节之后；现在从最终课件生成轻量锚点目录，正文筛选和阅读导航都定位所属章节。NumPy 参考代码原来在选读中被隐藏；章节通过可选 `codeConceptIds` 引用既有概念代码，由现有 CodeLab 显示，不复制代码源，完整专题也只显示一次。

八个章节的 ID／标题、概念代码及输出、实验、例题和误区数据与修改前逐字段一致。两个主线新图各展示一次，三个旧图锚点保留；未知路线／锚点继续安全回退。NumPy 独立核对向量差、数组形状、原始／转置／三行预测，并实际运行既有参考代码核对输出。

本地向量课验收：全量测试 1,191 通过、28 条件跳过，两种构建、目录和 8 项发布资源检查通过。200 个相关浏览器场景通过（单元 3／5 连续阅读 116、数学选读 8、数学加载 9、既有矩阵图 4、六单元衔接 44、概率图 9、新向量图 10），覆盖双语、桌面／390px、旧锚点及正确的下一节、键盘退出选读、刷新、图片失败、代码可见且不重复、空存储和历史数据逐字节不变。实看两张新图、双语图注和代码输出的手机截图；代码长行使用既有横向滚动。
