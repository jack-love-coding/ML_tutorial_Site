## Critical Issues

### CR-01: The six required interaction scenes do not implement play/pause

**File:** `/Users/jackky/Desktop/ML_tutorial_Site/.worktrees/phase28b-course/src/modules/optimizer-comparison/labs/TrainingLedgerScene.vue:9-11`, `BatchNoiseScene.vue:10-12`, `MomentumRmspropScene.vue:8-10`, `AdamDecayScene.vue:8-10`, `ScheduleCadenceScene.vue:9-11`, `CurveDiagnosisScene.vue:31-34`  
**Issue:** Every scene exposes only a one-step and reset action. There is no playing state, timer/animation loop, pause action, or cleanup. This contradicts the approved requirement that each dedicated lab supports play, pause, step, and reset; four course chapters cannot make up for the missing controls with the separate media player.

**Fix:** Add a shared, lifecycle-cleaned playback composable (for example `playing`, `play()`, `pause()`, `step()`, `reset()`, and `onBeforeUnmount(clearInterval)`) and render an accessible Play/Pause button in every scene. Add component/browser tests that prove playback advances one model step, pause stops it, and native controls retain their normal keyboard behavior.

### CR-02: Chinese learners receive English-only interactive labs

**File:** `/Users/jackky/Desktop/ML_tutorial_Site/.worktrees/phase28b-course/src/modules/optimizer-comparison/labs/TrainingLedgerScene.vue:9-15`, `BatchNoiseScene.vue:10-14`, `MomentumRmspropScene.vue:8-12`, `AdamDecayScene.vue:8-12`, `ScheduleCadenceScene.vue:9-13`, `CurveDiagnosisScene.vue:31-37`  
**Issue:** The course shell localizes its prose, but all six lazy scenes hard-code English headings, controls, captions, status text, table headers, and ARIA labels. None imports locale state or a `LocalizedCopy` map. This violates the repository rule that teaching content supplies both `zh-CN` and `en`, so the default Chinese course is not bilingual at the interaction point.

**Fix:** Move learner-visible scene copy into typed `LocalizedCopy` data (or per-scene localized copy), select it from `useI18n()`, and localize all ARIA labels and formatted status text as well as headings. Add a rendered zh-CN test for every scene rather than testing only the chapter-data objects.

### CR-03: The training ledger displays values that cannot come from its stated forward/loss/backward example

**File:** `/Users/jackky/Desktop/ML_tutorial_Site/.worktrees/phase28b-course/src/modules/optimizer-comparison/labs/sceneModels.ts:15-28`  
**Issue:** With `θ = [1, -0.5]`, the displayed forward value `ŷ = 0.625` and target `y = 1` imply an error of `-0.375`. The displayed gradient `[0.6, -0.25]` would require `x = [-1.6, 0.666…]`; substituting that `x` into the stated forward equation yields `-1.933…`, not `0.625`. The following optimizer update is engine-derived, but its input gradient and the visible forward/loss entries are static, unrelated literals. This breaks the phase's no-fabricated-values and formula/code/visual consistency requirements.

**Fix:** Define one explicit feature vector and label, compute `prediction`, loss, and gradients from those same inputs, and feed that computed gradient into `stepOptimizer`. Keep only values obtained from this calculation or a hash-bound published asset; add a numerical test asserting the equation, gradient, loss, and displayed update agree.

### CR-04: The Banknote artifact check verifies self-reported metadata, not that the published metrics are reproducible

**File:** `/Users/jackky/Desktop/ML_tutorial_Site/.worktrees/phase28b-course/scripts/optimizer-comparison/build-assets.mjs:236-261`  
**Issue:** `--check` hashes the already-published JSON and compares only source hash, split counts, and preprocessing. Lines 242-245 do not recompute the frozen logistic run or compare its parameters, validation metrics, final test metrics, selected configuration, or evaluation order with the artifact. Consequently, changing the result values and updating the manifest hash leaves the check and all new Banknote assertions passing: the tests at `tests/optimizer-assets.test.ts:39-51` and `tests/optimizer-scene-models.test.ts:49-63` merely read self-reported JSON fields. The claimed real, validation-only, exactly-one-final-test result is therefore not proven by the release gate.

**Fix:** Extract the deterministic Banknote computation into a pure, testable function. In `--check` (or an equivalent authoritative verification command), regenerate it in memory from the canonical source and assert deep equality for configuration, train-only statistics, trained parameters, validation result, and the one frozen final-test result; fail if any differ. Add mutations of both a metric and `parametersAfterTraining` to prove the check rejects them.

### CR-05: The final-scene load-error path discards the teaching values instead of providing the required semantic fallback

**File:** `/Users/jackky/Desktop/ML_tutorial_Site/.worktrees/phase28b-course/src/modules/optimizer-comparison/labs/CurveDiagnosisScene.vue:13-26`, `CurveDiagnosisScene.vue:33-37`  
**Issue:** If either asset fetch fails, `fallbackRows` becomes one row of `unavailable` values and the Banknote table is also `Unavailable`. The component thus has no same-value load-error fallback for either the controlled curves or Banknote metrics, despite claiming a semantic fallback. The reduced-motion CSS does not solve this failed-data path.

**Fix:** Make a hash-bound semantic snapshot available to the component (for example, a generated typed module produced from the same published artifacts), render it when fetches fail, and mark it as the published snapshot. Preserve the same comparison and Banknote values in that path; test a rejected/non-OK fetch for both assets and assert the displayed rows match the normal loaded state.
