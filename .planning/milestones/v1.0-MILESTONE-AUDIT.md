# Milestone v1.0 Audit

## Executive Summary

Milestone v1.0 is **not ready for clean archival** under the current GSD audit rules.

The implementation is substantially present: repository inspection and integration checks found 18 of 26 requirements fully wired, 8 partially wired, and 4 of 6 representative end-to-end flows complete. The current test suite passes 755 of 755 tests.

The canonical milestone record tells a different story. All 26 v1 requirements are still unchecked in `REQUIREMENTS.md`, and none appears in both a canonical phase `VERIFICATION.md` requirement table and matching `SUMMARY.md` frontmatter. Under the required three-source rule, all 26 requirements are therefore orphaned and cannot be counted as satisfied.

Two implementation defects are also release-significant:

1. Checkpoint answers do not advance durable progress.
2. Canonical Math Lab and Data Lab lesson URLs lose the requested lesson identity.

## Critical Integration Gaps

### 1. Checkpoint activity does not advance durable progress

The three checkpoint components hold answers in component-local reactive state:

- `src/components/AlgorithmCheckpointQuiz.vue`
- `src/modules/math-lab/components/CheckpointQuiz.vue`
- `src/modules/data-lab/components/DataCheckpointQuiz.vue`

Their parent pages update last-visited state, but they do not call the available completion and quiz-attempt mutation functions. Several mutation helpers and `SelfPacedCompletionButton` are therefore runtime-orphaned. Existing layout tests explicitly assert the absence of this wiring.

Impact:

- A learner can answer a checkpoint without completing the module in storage.
- `selectContinueLearning()` cannot reliably recommend the next lesson for a fresh learner.
- PROG-04 and VAL-04 remain partial.
- The primary “learn, checkpoint, continue” flow is broken.

### 2. Math Lab and Data Lab deep links lose lesson identity

`src/curriculum/routes.ts` retains `lessonId` only for algorithm-backed modules. Canonical Math Lab and Data Lab URLs resolve to their module root:

- `/learn/optimization/v3-banknote-optimization-primary-lab`
- `/learn/numerical-data/table-to-vector`

Impact:

- Shared links do not reopen the intended lesson.
- Canonical navigation cannot preserve the learner's active Math/Data lesson.
- ROUTE-01 and VAL-04 remain partial.

## Post-audit Decisions and Closure Updates

On 2026-07-24, the Math/Data deep-link implementation gap was closed:

- Math Lab canonical targets now redirect to the existing Math Lab page with the requested lesson hash.
- Data Lab canonical targets now redirect to the existing Data Lab page with the requested lesson hash.
- Redirects preserve query state, reject unsafe lesson ID shapes, and remain compatible with lazy-loaded course pages.
- Tests use real catalog-owned targets (`optimization/v3-banknote-optimization-primary-lab` and `numerical-data/table-to-vector`) rather than invented anchors.
- Validation passed: 756/756 tests, production build, and GitHub Pages build.

The user explicitly deferred checkpoint persistence until the backend database and user progress model are designed. PROG-04 remains an accepted known limitation, but it is not a current frontend-content blocker.

The overall audit status remains `gaps_found`: the route implementation fix does not retroactively create the missing three-source requirement provenance, and the deferred progress gap is still open.

## Recommended Closure Sequence

1. **Reconcile milestone traceability.** Create retroactive canonical verification/summary coverage for Curriculum V2 phases 1-7, update all 26 requirement checkboxes and traceability statuses from evidence, and rerun the milestone audit.
2. **Close non-critical partials.** Decide whether CURR-04, HOME-01, HOME-02, LESSON-01, and LAB-02 are required for v1.0 or should be explicitly narrowed/deferred before archival.
3. **Return to checkpoint persistence with the backend milestone.** Design completion and quiz-attempt writes together with database identity, synchronization, and user progress ownership.

The milestone may be archived only by explicitly accepting these gaps, or after the closure work produces a clean follow-up audit.
